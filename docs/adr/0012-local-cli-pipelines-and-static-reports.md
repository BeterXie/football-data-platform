# ADR-0012: 第一阶段采用本地命令行流水线与静态报告

- 状态：已接受
- 日期：2026-07-16

## 背景

第一阶段的主要风险是数据覆盖、时间快照、质量门槛和训练闭环，而不是前端交互。现有仓库已有命令行脚本、Parquet/JSON 产物和静态 HTML 报告基础，但部分日常流程仍依赖复制 notebook 或把采集、预测和展示混在一个脚本中。

## 决策

1. 第一阶段通过本地、可重复执行的命令行任务完成数据发现、采集、补采、规范化、快照、训练数据构建、模型评估和报告生成。
2. 正式数据产物包括不可变原始快照、版本化 Parquet/JSON 数据集、运行清单、诊断记录和静态 HTML 报告。
3. 命令行任务必须尽量幂等、可断点重跑，并以明确退出码和机器可读诊断报告成功、部分成功或失败。
4. notebook 只用于探索、研究和临时分析；正式每日或赛季流水线不得依赖复制 notebook 运行。
5. 静态 HTML 是结构化数据的展示层，不是事实来源，也不能包含无法从对应数据版本复现的隐式计算。
6. 第一阶段不建设公开 Web 服务、移动端或对外 API。
7. 本地任务调度方式保持可替换，可以由 Windows 任务计划、其他本地调度器或手动命令触发，但业务逻辑不能写死在调度器中。

## 影响

- 核心逻辑需要下沉到可复用模块，脚本只负责编排和参数解析。
- 每次运行需要保存参数、代码或解析器版本、输入与输出数据版本、开始结束时间和错误摘要。
- 现有每日 notebook 和一体化脚本应逐步迁移，不要求立即删除历史文件。
- 将来建设 API 或 Web UI 时，只能消费已经稳定的领域数据契约。

## 未决问题

- 各任务的具体运行频率、超时和重试预算。
- 本地失败通知与人工复核入口。
- 数据和 HTML 产物的保留、压缩与清理策略。
