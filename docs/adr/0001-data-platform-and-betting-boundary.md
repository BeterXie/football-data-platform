# ADR-0001: 数据平台为核心，价值投注为下游模块

- 状态：已接受
- 日期：2026-07-16

## 背景

初始设计把仓库定义为世界杯比赛预测系统，主链是球队实力、比赛概率和赛事模拟。随着目标演进，系统需要长期拉取赛事新闻和赛事信息，归档赛后与球员数据，并形成可用于分析和训练的数据资产。

价值投注仍然需要比赛概率和市场数据，但它不应拥有上游数据采集、清洗、归档或训练职责。

## 决策

1. 系统核心定位为足球数据采集、标准化、归档、分析与训练数据准备平台。
2. 数据主链负责赛事与新闻采集、赛后数据沉淀、球员和球队分析，以及训练数据集的生成与版本管理。
3. 价值投注是独立下游模块，只根据上游准备完成的数据进行概率、市场价值和投注风险分析。
4. 价值投注模块不得成为数据采集或归档的隐式入口。其运行失败不得阻断数据主链。
5. “准备完成”的数据必须通过显式、可验证的数据契约定义；该契约将在后续设计决策中确定。

## 影响

- 原始世界杯预测设计不再是当前系统的总设计，只保留为历史设计依据。
- 预测、赛事模拟和价值投注均作为数据平台的下游消费者建模。
- 数据采集代码与投注逻辑需要通过稳定的数据契约解耦。
- 当前每日投注流程若直接抓取、修补或持久化基础数据，应在后续迁移中拆分职责。

## 未决问题

- 第一阶段必须覆盖的赛事范围与优先级。
- “准备完成”的比赛、球队和球员数据的最低完整性标准。
- 训练数据快照、标签和模型版本之间的可追溯关系。
- 赛前预测、赛后分析和价值投注各自的运行频率及服务等级。
