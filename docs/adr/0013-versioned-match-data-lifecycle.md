# ADR-0013: 每场比赛采用显式、版本化的数据生命周期

- 状态：已接受
- 日期：2026-07-16

## 背景

赛程被发现、赛前信息齐备、比赛完赛、赛后统计发布和数据可用于训练是不同事件。若只根据文件存在或比赛状态判断“数据完整”，部分抓取结果会被误送入模型训练或价值投注。

## 决策

1. 每场比赛的数据版本通过以下生命周期状态推进：
   - `discovered`
   - `t24-ready`
   - `lineups-ready`
   - `finished-stats-pending`
   - `archived-complete`
   - `training-ready`
2. `discovered` 表示比赛已具有规范赛事、赛季、球队、计划开赛时间和来源身份。
3. `t24-ready` 表示对应早期赛前快照已经通过该快照的数据完整性与时间校验。
4. `lineups-ready` 表示双方官方首发已确认，最终赛前快照已经生成并通过校验。
5. `finished-stats-pending` 表示 90 分钟结果已确认，但规定的赛后球队或球员数据仍未全部归档或验证。
6. `archived-complete` 表示该完整性配置要求的赛后事实和统计已经归档，并保留来源与质量诊断。
7. `training-ready` 表示该数据版本进一步通过预测时点、防泄漏、标签、必填字段和训练任务规则。
8. 状态只能由显式校验器根据版本化数据和证据计算，不能由脚本手工写死或通过单一文件存在推断。
9. 比赛改期、来源纠错或统计修订不覆盖旧记录，而是生成新的数据版本和状态历史。旧赛前快照继续保留其当时事实。

## 影响

- 采集任务与训练任务通过状态和数据契约解耦。
- 完赛结果可以先归档，缺失统计由后续补采任务继续推进。
- 报告需要显示当前状态、缺失项、最后尝试时间和数据版本。
- 同一场比赛可能同时保留多个历史赛程版本、赛前快照和修订后的赛后数据版本。

## 未决问题

- 各状态的具体必填字段与超时策略。
- `training-ready` 是否按不同训练任务拆分为多个资格配置。
- 下游价值投注的独立 `betting-ready` 校验规则。
