# ADR-0008: 比赛模型采用基准与挑战者晋级机制

- 状态：已接受
- 日期：2026-07-16

## 背景

初始设计把 XGBoost 固定为泊松模型后的正式修正层，但当前每日流程并未实际加载经过验证的 XGBoost 模型。把某个算法预先写成必选架构，会掩盖训练缺失、样本内过拟合和概率不一致问题。

## 决策

1. Dixon-Coles 低比分校正的独立泊松比分模型作为第一版透明、可解释的正式基准模型。
2. 机器学习或其他统计模型作为挑战者，使用与基准一致的赛前快照、预测目标和评估样本。
3. 不指定 XGBoost 为必选修正层。算法只有通过晋级标准后才能成为正式模型的一部分。
4. 模型晋级必须采用按时间滚动的样本外验证，禁止以训练集或随机打乱后造成时间穿越的结果作为上线证据。
5. 核心评估使用真实比赛结果上的 Brier、LogLoss、可靠性分析和必要的分组诊断，并与同一时点的真实去水市场概率比较。
6. 禁止用模型概率加噪声生成合成赔率，再用这些赔率证明模型具有投注优势。
7. 正式模型和挑战者必须带模型版本、训练数据版本、特征版本、快照类型、评估区间和可回滚产物。
8. 挑战者只有在预先定义的最小样本和观察周期内稳定改善概率预测质量，且没有显著破坏关键分组时，才能升级为正式模型。
9. 投注收益只作为下游观察指标，不能替代概率评分和校准检验成为模型晋级依据。

## 影响

- 原设计中的“泊松 + XGBoost”改为可替换的模型组合，而非固定架构。
- Dixon-Coles 数学定义、比分网格归一化和所有派生盘口必须有独立单元测试。
- 每次晋级都需要保存对照报告，说明相对当前正式模型和市场基准的变化。
- 样本不足时允许挑战者继续影子运行，但不得根据短期 ROI 直接上线。

## 未决问题

- 模型晋级所需的最小比赛数、最短观察周期和改善阈值。
- 可靠性分箱、置信区间和显著性评估方法。
- 挑战者输出联合比分分布的具体建模方式。
- 市场赔率是否进入某个独立模型版本的输入。
