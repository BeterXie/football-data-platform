# ADR-0016: 数据采用 raw、canonical、derived 三层架构

- 状态：已接受
- 日期：2026-07-16

## 背景

当前仓库同时存在网页缓存、来源 JSON、CSV、Parquet、模型输入和 HTML 报告，部分下游代码直接理解来源字段。随着赛事和来源增加，如果不固定数据分层，来源页面变化会直接破坏训练和投注流程，也无法复现历史预测。

## 决策

1. 平台数据固定分为 `raw`、`canonical` 和 `derived` 三层。
2. `raw` 层保存来源原文、HTML、JSON、响应或人工导入文件，以及来源、抓取时间、目标事件时间、请求参数、校验和和采集器版本。原始记录不可变。
3. `canonical` 层保存使用平台实体 ID 的规范化事实，包括赛事、赛季、赛程、比赛版本、球队、球员、阵容、事件、统计、新闻证据、结构化赛前事件和市场快照。
4. `derived` 层保存可重建产物，包括赛前特征快照、球队长期基线、阵容增量、球员角色画像、训练数据集、模型产物、预测、评估和静态报告。
5. 每个 canonical 或 derived 产物必须能够追溯输入记录、转换或解析器版本、生成时间和质量状态。
6. 模型、评估、赛事模拟和价值投注只能消费明确版本的 canonical 或 derived 数据，不得在业务逻辑中直接解析来源网页。
7. 来源修订或解析器升级不覆盖旧版本。重新规范化或派生时生成新版本，并保留旧版本用于复现历史结果。
8. CSV、Markdown 和 HTML 可以作为交换或展示镜像，但其内容不能成为高于规范 Parquet/JSON 或目录清单的事实来源。

## 影响

- 采集器只负责产生 raw 记录和采集诊断；规范化、实体解析和特征构建是独立步骤。
- 数据目录、运行清单和版本命名需要统一，现有散落文件可逐步迁移。
- 静态报告必须引用预测、数据和模型版本，不能包含无血缘的手工数字。
- 离线重放可以从 raw 层重新执行解析、规范化和派生，而无需重新访问网站。

## 未决问题

- 三层目录的最终命名、分区和文件布局。
- canonical 元数据与实体映射使用 SQLite、Parquet 或其他本地目录技术的分工。
- 原始快照和历史派生产物的压缩与保留策略。
