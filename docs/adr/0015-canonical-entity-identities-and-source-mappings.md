# ADR-0015: 使用平台稳定实体 ID 和带审计的来源映射

- 状态：已接受
- 日期：2026-07-16

## 背景

FBref、新闻、阵容和赔率来源对同一赛事、球队、球员和比赛使用不同 ID、拼写与语言。名称会变化，球员会转会，球队会更名，比赛也可能改期或交换场地。若把来源 ID 或展示名称当作平台主键，历史关联和训练样本会逐渐分裂。

## 决策

1. 平台生成并拥有稳定的 `competition_id`、`season_id`、`team_id`、`player_id` 和 `match_id`。
2. 平台实体 ID 一旦分配不因来源变化、中文译名、球员转会或比赛改期而改变。具体 ID 编码格式由实现设计决定，但不得包含可变展示字段。
3. 每个外部来源 ID 通过独立来源映射记录关联到平台实体，至少保存来源、实体类型、来源 ID、有效时间、匹配规则、置信度和创建时间。
4. 中英文名称、缩写、旧名和来源拼写保存为别名，只用于展示、搜索和生成匹配候选，不作为唯一键。
5. 自动匹配只能在达到对应实体类型的置信度门槛后生效。低置信度或冲突匹配进入人工复核，不得静默合并。
6. 人工 override 优先级最高，但必须保存修改人或运行、时间、理由、原候选和证据，不能只覆盖结果。
7. 球员转会通过带起止时间的球队注册或效力关系表达，不创建新球员实体。
8. 比赛改期和场地调整通过比赛版本与赛程事件表达，不创建重复比赛；只有证据表明来源记录代表不同比赛时才分配新 `match_id`。

## 影响

- 所有规范化和派生数据使用平台实体 ID 关联，来源名称仅作为附带字段。
- 数据采集器先保存来源事实，再由身份解析层建立或复用平台实体。
- 历史映射修订需要重新计算受影响的规范化数据与训练资格，但保留旧映射版本。
- 当前零散的 FBref、懂球帝和赔率 ID 映射需要迁移到统一映射模型。

## 未决问题

- 平台 ID 的具体格式和生成方式。
- 各实体类型自动匹配的置信度阈值。
- 人工复核界面或本地工作流。
- 同名球员、青年队与一线队以及二队实体的消歧规则。
